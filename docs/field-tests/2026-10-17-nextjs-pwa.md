# 실전 적용 기록 — 휴대폰 우선 Next.js PWA (2026-10-17)

README 예시를 만들며 한 실전 검증. 대상 레포의 소스·분석 결과는 이 레포에 넣지 않았고(README 예시 이미지는 사용자 동의로 사용), 일반화한 문제와 수치만 적습니다. 원본은 읽기만 했고 스크래치 복사본에서 진행했습니다.

## 대상

- Next.js 16 App Router PWA. 화면이 route group(`app/(student)/…`, `(teacher)`, `(admin)`)으로 나뉘고, 본문이 휴대폰 폭(390px) 기준
- DB·소셜 로그인 없이는 띄울 수 없음 → 캡처는 레포의 확인용 목업(실제 컴포넌트·빌드된 CSS로 만든 정적 화면)에서 가져옴
- 화면 60개 중 수강생 화면 4개 + 로그인만 분석(`screens.include`)

## 흐름과 수치

| 단계 | 결과 |
| --- | --- |
| init·inventory | `nextjs` 감지기로 60개, include로 5개 |
| 화면 분석 | 서브에이전트 2개, 5화면 모두 통과(첫 실행에서 문구 검사 실패 4건 → 아래 2번) |
| 소개·워크플로우 | 기능 5, 워크플로우 3(예약 신청, 수강권 확인 후 예약, 예약 취소) |
| 산출물 | HTML(handover) |

## 발견한 문제와 처리

| # | 문제 | 처리 |
| --- | --- | --- |
| 1 | 산출물의 경로가 `/(admin)/admin`처럼 route group을 포함 — 사용자가 주소창에서 볼 수 없는 경로 | inventory의 route(파일 구조 열쇠)는 그대로 두고, 산출물에 보일 때 route group·병렬 슬롯을 뺀다 |
| 2 | JSX에서 문장이 `<b>`·`<br/>`·`{" "}`·`{/* */}`로 끊기면 화면에 보이는 대로 적은 문구가 근거 검사에 실패 — 에이전트가 문장 일부만 적거나 공백을 뺀 자리 표시를 씀 | 검사 창에서 인라인 태그·JSX 주석을 빼고 `{" "}`를 공백으로 바꾼 글자에서도 찾는다 |
| 3 | 휴대폰 우선 앱을 1280 폭으로 찍으면 대부분 여백이고, 산출물에서 데스크톱 폭으로 늘어남 | `capture.device: mobile`(캡처 390×844 2배 밀도, GIF 390×700), 산출물은 400px 폭 틀로 가운데 |

## 고치지 않은 것

- 앱을 띄울 수 없을 때 목업에서 캡처를 가져오는 기능은 넣지 않았습니다(이번에는 수동). 목업 형식이 프로젝트마다 달라 일반화하기 어렵습니다
- 접근 권한이 역할이 아니라 리다이렉트 함수로 정해지는 화면은 역할을 `medium`으로 적습니다(규칙 그대로)
