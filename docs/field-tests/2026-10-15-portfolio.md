# 실전 적용 기록 — 개인 포트폴리오 사이트 (2026-10-15)

docent 1.0 전 실전 검증. 대상 레포의 소스·분석 결과·캡처는 개인 정보라 이 레포에 넣지 않았고, 여기에는 일반화한 문제와 수치만 적습니다. 원본 레포는 읽기만 했고, 스크래치 복사본에서 SKILL.md 흐름을 그대로 따랐습니다.

## 대상

- Next.js 16(App Router) + pnpm, TypeScript, CSS Modules, 소스 약 135개 파일
- 로그인·입력 양식이 없는 소개형 사이트. 다크 테마, 스크롤하면 나타나는 애니메이션, 기능 플래그로 숨긴 화면, 데이터가 비면 404가 되는 동적 화면, PDF 생성 전용 화면이 있음

## 흐름과 수치

| 단계 | 결과 | 소요 |
| --- | --- | --- |
| init·inventory | 감지기 `nextjs`가 화면 12개 검출(`not-found`·`opengraph-image`·`robots`·`sitemap`은 올바르게 제외) | 1초 미만 |
| 화면 목록 확인 | PDF 생성 전용 `/export/*` 3개를 제외해 9개(사용자 확인 단계에 해당) | — |
| 화면 분석 | screen-analyzer 서브에이전트 3개 병렬(화면 4개씩) → 지시 보강 뒤 2개로 9개 재분석 | 배치당 2~5분 |
| summary·scenarios | summary-writer 1개, scenario-writer 1개 + 실패한 3개 재작성 | 1~3분 |
| run | `pnpm install --frozen-lockfile` → `pnpm build && pnpm start` | 32초 |
| crawl | 방문 7, 목록에 없는 경로 0, 도달 못 함 5(메뉴·링크가 없는 숨은 화면 — 정상) | 4초 |
| capture·record | 캡처 7(1개는 기능 플래그로 404 — 정상 보고), GIF 6 | 74초 |
| build | portfolio 프리셋 HTML·README·PDF(18쪽)·PPTX(12장), 같은 입력으로 두 번 빌드 시 HTML·README 바이트 동일 | 7초 |

## 발견한 문제와 처리

| # | 문제 | 처리 |
| --- | --- | --- |
| 1 | 화면 파일 목록에 `.module.css`·이미지 import가 섞여 스타일만 고쳐도 재분석 대상이 됨 | 스타일·이미지·글꼴 import 제외(테스트 추가) |
| 2 | 메뉴에 없는 화면을 크롤이 찾을 단서가 부족 | `sitemap.xml`의 경로를 시작점으로 사용. 사이트맵은 운영 도메인으로 적히므로 경로만 씀 |
| 3 | 여러 줄로 나뉜 문구가 근거 검사(±5줄)를 통과하지 못함 | 공백을 모은 창 전체에서도 찾음 |
| 4 | 분석 에이전트가 자기 화면만 검증할 방법이 없음 | `docent validate <화면ID>` 추가 |
| 5 | 공통 헤더·메뉴·푸터가 화면마다 반복돼 버튼의 70~90%를 차지 | screen-analyzer 지시: 공통 레이아웃은 넣지 않음 → 화면당 버튼 11~22개가 0~8개로 줄어듦 |
| 6 | 데이터 파일에 있는 라벨, 아이콘 버튼, 데이터로 채워지는 제목, 기능 플래그로 숨긴 화면, 읽기 전용 상세 레이어, 다른 화면을 끼워 넣은 화면, 문장형 h1, 소개 문구의 처리 기준이 없음 | screen-analyzer 지시에 각 기준 추가 |
| 7 | 소개형 사이트에는 "업무 단위 워크플로우 2~6개"가 맞지 않음, 지금 열리지 않는 화면·메뉴 없는 화면 처리 기준 없음 | summary-writer 지시 보강 |
| 8 | 보이는 글자와 접근성 이름이 다른 요소(번호 붙은 목차, aria-label이 따로 있는 카드 버튼)를 클릭하지 못함 | `click`이 정확한 이름이 없으면 보이는 글자로 찾음 |
| 9 | 녹화 브라우저에 클립보드 권한이 없어 "주소 복사" 시연 실패 | 캡처·녹화 컨텍스트에 클립보드 권한 |
| 10 | 데이터가 없어 열 주소가 없는 동적 화면의 시나리오 기준 없음 | scenario-writer 지시: 시나리오를 쓰지 않고 보고(캡처 없이 매뉴얼에 들어감) |
| 11 | 스크롤하면 나타나는 내용이 전체 페이지 캡처에서 비어 찍힘 | 캡처 전에 끝까지 스크롤 후 맨 위로, 움직임 줄이기(`prefers-reduced-motion`) 켬 |
| 12 | portfolio 카드에 세로로 긴 캡처가 그대로 들어가 카드가 매우 길어짐 | 카드 캡처를 16:10 비율 위쪽만 표시 |
| 13 | 로그인이 없는 사이트에서 HTML "사용자 역할"이 빈 제목 | "로그인 없이 사용합니다" 표시 |

## 고치지 않은 것

- 기능 플래그로 404가 되는 화면은 캡처 실패로 보고됩니다. 사실 그대로라 그대로 둡니다(분석 JSON의 `unknowns`에 이유가 있음).
- `messages`에 없는 구획 제목은 시나리오의 `expectText`로 쓸 수 없어 `wait`로 대신합니다. 근거 원칙상 의도된 동작입니다.
